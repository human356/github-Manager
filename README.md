# 🐙 مدیریت‌کننده گیت‌هاب (GitHub Manager)

یک وب‌اپلیکیشن کامل برای مدیریت مخازن گیت‌هاب با **React** (بدون نیاز به build) و یک **سرور Node.js خالص** با دیتابیس **SQLite**.

با حساب گیت‌هاب خودتان لاگین کنید (توکن شخصی یا Device Flow)، به **همه‌ی مخازن — از جمله خصوصی** دسترسی داشته باشید، فایل‌ها و پوشه‌ها را بسازید، ویرایش کنید، حذف کنید، جابه‌جا یا کپی کنید؛ در نهایت با دکمه‌ی **«ثبت نهایی»** همه‌ی تغییرات در قالب **یک کامیت واقعی** روی مخزن انتخابی ثبت می‌شود و هویت برنامه + حساب شما به‌عنوان **مشارکت‌کنندگان** در کامیت ثبت می‌شوند.

---

## ✨ امکانات

| دسته | قابلیت‌ها |
| --- | --- |
| احراز هویت | ورود با توکن شخصی (PAT کلاسیک یا Fine-grained) یا Device Flow؛ توکن فقط در SQLite محلی ذخیره می‌شود |
| مخازن | فهرست همه‌ی مخازن (عمومی/خصوصی/سازمانی)، ساخت مخزن جدید، ویرایش نام/توضیح/نوع، حذف مخزن، ساخت شاخه‌ی جدید |
| مدیریت فایل | درخت کامل فایل‌های مخزن، ساخت فایل و پوشه، ویرایش متنی، بارگذاری فایل باینری (تا ۲۰MB)، دانلود |
| عملیات پوشه/فایل | **حذف، انتقال (rename)، کپی** — هم روی فایل و هم روی کل پوشه (بازگشتی) |
| ثبت تغییرات | صف تغییرات محلی (Stage) با امکان واگردانی تک‌تک آیتم‌ها؛ دکمه‌ی «ثبت نهایی» همه را در **یک کامیت** روی شاخه‌ی انتخابی ثبت می‌کند |
| هویت کامیت | نویسنده‌ی کامیت = هویت برنامه (قابل تنظیم)؛ حساب شما به‌صورت `Co-authored-by` اضافه می‌شود تا هر دو مشارکت‌کننده ثبت شوید |
| رابط کاربری | فارسی، راست‌به‌چپ، تم تیره به سبک گیت‌هاب، کاملاً واکنش‌گرا |

## 🏗️ معماری

```
github-manager/
├── server.js            ← کل سرور: HTTP + API + SQLite + موتور کامیت
├── public/index.html    ← کل رابط کاربری (React + htm، همه‌چیز inline — بدون CDN و بدون build)
├── data/                ← دیتابیس SQLite (خودکار ساخته می‌شود)
└── package.json
```

- **بدون هیچ پکیج npm**: سرور از `node:http`، `node:sqlite` و `fetch` داخلی Node استفاده می‌کند؛ رابط کاربری React و htm را داخل خود فایل HTML دارد. یعنی **نیازی به `npm install` نیست**.
- **دیتابیس**: جدول `settings` (توکن، هویت نویسنده) و جدول `changes` (صف تغییرات هر مخزن تا قبل از کامیت).
- **موتور کامیت** از Git Data API گیت‌هاب استفاده می‌کند: دریافت درخت پایه → اعمال ترتیبی تغییرات → آپلود بلاب‌ها → ساخت درخت جدید → ساخت کامیت → به‌روزرسانی شاخه. کامیت‌ها اتمیک‌اند و اگر شاخه جلو رفته باشد خطای conflict می‌گیرید، نه بازنویسی.

## 🚀 اجرا

پیش‌نیاز: **Node.js نسخه 22.5 یا بالاتر** (برای `node:sqlite`؛ روی Node 22/23 با پرچم `--experimental-sqlite` اجرا کنید، روی Node 24+ بدون پرچم).

```bash
node server.js
# یا
npm start
```

سپس در مرورگر: **http://localhost:3000**

> ⚠️ توصیه‌ی امنیتی: سرور فقط روی `127.0.0.1` گوش می‌دهد. آن را روی شبکه‌ی عمومی اجرا نکنید؛ توکن گیت‌هاب شما داخل دیتابیس محلی است.

## 🔑 نحوه‌ی ورود

### روش ۱ — توکن شخصی (پیشنهادی)
1. در گیت‌هاب: `Settings → Developer settings → Personal access tokens → Tokens (classic)`
2. توکن جدید با دسترسی‌های **`repo`** (دسترسی کامل به مخازن خصوصی) و در صورت نیاز **`delete_repo`** (برای حذف مخزن) بسازید.
3. توکن را در صفحه‌ی ورود برنامه بچسبانید.

> توکن Fine-grained هم پشتیبانی می‌شود؛ فقط باید به مخازن موردنظر دسترسی `Contents: Read and write` (و `Metadata`) بدهید.

### روش ۲ — Device Flow
1. در `github.com/settings/developers` یک **OAuth App** بسازید و **Enable Device Flow** را فعال کنید.
2. **Client ID** آن را در تب Device Flow برنامه وارد کنید و کد نمایش‌داده‌شده را در `github.com/login/device` تأیید کنید.

## 📖 راهنمای استفاده

1. **ورود** → فهرست مخازن شما نمایش داده می‌شود (با جست‌وجو، نشان خصوصی/عمومی، زبان، ستاره، شاخه‌ی پیش‌فرض).
2. روی **«مدیریت فایل‌ها»** کلیک کنید → درخت فایل‌های مخزن + ویرایشگر + پنل «تغییرات در انتظار ثبت».
3. عملیات‌ها (همه ابتدا **محلی** ثبت می‌شوند و چیزی روی گیت‌هاب نمی‌رود):
   - **فایل جدید / پوشه جدید**: از دکمه‌های بالای درخت یا آیکون‌های کنار هر پوشه.
   - **ویرایش**: روی فایل کلیک کنید، متن را تغییر دهید و «ثبت در صف تغییرات» را بزنید.
   - **حذف / انتقال / کپی**: از آیکون‌های کنار هر فایل/پوشه (برای پوشه‌ها بازگشتی اعمال می‌شود).
   - **بارگذاری فایل**: دکمه‌ی «بارگذاری فایل…» (چندتایی، باینری هم قابل قبول).
   - هر آیتم صف با دکمه‌ی × قابل واگردانی است؛ «خالی‌کردن صف» همه را دور می‌ریزد.
4. **ثبت نهایی**: پیام کامیت را بنویسید و دکمه‌ی سبز «ثبت نهایی روی گیت‌هاب» را بزنید. نتیجه (SHA کامیت + شمار تغییرات + لینک) نمایش داده می‌شود.
5. از ⚙ **تنظیمات** می‌توانید نام/ایمیل هویت برنامه و فعال‌بودن Co-author را تغییر دهید.

## 🗄️ دیتابیس (SQLite)

فایل `data/github-manager.db` با دو جدول:

```sql
settings(key TEXT PRIMARY KEY, value TEXT)                 -- token, scopes, author_name, author_email, coauthor
changes(id, repo, op, kind, path, dst, content, is_binary, size, created_at)  -- صف تغییرات هر مخزن
```

برای بازنشانی کامل، برنامه را متوقف کنید و پوشه‌ی `data/` را حذف کنید.

## 🔒 نکات امنیتی

- توکن فقط در SQLite روی همین سیستم ذخیره می‌شود و به هیچ سروری جز api.github.com ارسال نمی‌شود.
- اعتبارسنجی مسیر در سرور (جلوگیری از `..`، `.git`، کاراکترهای کنترلی).
- محدودیت حجم: فایل متنی تا ۱۰MB، باینری تا ۲۰MB (محدودیت blobs API گیت‌هاب ~100MB است؛ برای اطمینان کمتر گذاشته شده).
- کامیت بدون force است؛ شاخه‌های محافظت‌شده رد می‌شوند.

## 🛠️ عیب‌یابی

| مشکل | راه‌حل |
| --- | --- |
| `node:sqlite` در دسترس نیست | Node را به 24+ ارتقا دهید یا `node --experimental-sqlite server.js` |
| مخازن خصوصی دیده نمی‌شوند | توکن باید دسترسی `repo` داشته باشد (Classic) یا `Contents` (Fine-grained) |
| حذف مخزن خطا می‌دهد | دسترسی `delete_repo` به توکن بدهید (موسسه‌ی گیت‌هاب به‌طور پیش‌فرض اجازه‌ی حذف نمی‌دهد) |
| خطای «سهمیه به پایان رسید» | Rate limit گیت‌هاب؛ چند دقیقه صبر کنید |
| «شاخه تغییر کرده» | مخزن جای دیگری تغییر کرده؛ درخت را به‌روزرسانی و دوباره ثبت کنید |
